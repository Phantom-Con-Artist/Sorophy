# Code of Conduct

## 1. Purpose

This Code of Conduct defines the standards for participation in the **Orb Engine** and **Orbis Project** community.

The goal is a technical environment where contributors can:

- discuss engineering decisions directly
- challenge designs without attacking people
- report defects without being dismissed
- review code based on evidence
- disagree without harassment
- collaborate without discrimination or intimidation

Technical disagreement is expected. Personal hostility is not.

## 2. Expected Behavior

Participants are expected to:

- Treat other participants as people, not targets.
- Critique code, proposals, tests, documentation, and technical decisions rather than attacking someone's character.
- Give reproducible evidence when reporting a defect or performance problem.
- Accept that maintainers may reject a technically reasonable proposal when it conflicts with the project's scope or architecture.
- State uncertainty when evidence is incomplete.
- Respect different levels of experience.
- Keep discussions relevant to the project.
- Protect private information shared during project work.
- Follow applicable repository, platform, and licensing rules.

## 3. Technical Disagreement

Orb Engine is intentionally strict about correctness, invariants, API design, serialization behavior, and testing.

It is acceptable to say:

> "This implementation can leave the adjacency index inconsistent after relationship removal."

It is not acceptable to say:

> "Only an idiot would write this."

Strong criticism of an implementation is allowed. Insults directed at a person are not.

Maintainers and reviewers may reject code, request substantial changes, or challenge assumptions. They should explain the technical reason when practical.

## 4. Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, threats, or intimidation
- Personal attacks or sustained hostile targeting
- Discriminatory comments or conduct based on protected characteristics
- Sexual harassment or unwelcome sexual attention
- Publishing private or identifying information without permission
- Deliberate impersonation intended to deceive
- Repeated unwanted contact
- Deliberate disruption of project spaces
- Retaliation against someone who reports misconduct in good faith
- Malicious code or documentation changes submitted under the pretense of ordinary contribution
- Deliberate submission of known-broken code while concealing the known defect
- Using project infrastructure to facilitate abuse, harassment, or illegal activity

## 5. Code Review Conduct

Code review must remain technical.

Reviewers should identify the specific problem, expected behavior, and relevant evidence where practical.

Contributors should respond to review comments about the work rather than the reviewer personally.

A maintainer may close a discussion when the technical question has been resolved or when continued discussion is no longer productive.

## 6. Reporting a Conduct Issue

For conduct concerns, contact the project maintainer privately using the maintainer contact mechanism listed in the repository's README.

A useful report should include:

- what happened
- where it happened
- when it happened
- the people or accounts involved, when known
- relevant links, messages, or other evidence
- whether the issue is ongoing
- whether you believe there is an immediate safety concern

Please avoid forwarding unrelated private information.

## 7. Security-Sensitive Situations

If a conduct issue also exposes credentials, private data, security vulnerabilities, or other sensitive information, do not post those details publicly.

Use a private reporting channel and provide only the information required for investigation.

## 8. Maintainer Response

Maintainers may take action when this Code of Conduct is violated, including:

- requesting that a participant stop the behavior
- deleting or moderating inappropriate project content
- closing discussions or issues
- restricting participation in project spaces
- removing contribution or review privileges
- temporarily or permanently banning participation
- reporting serious cases to the relevant platform or authorities when required

The action taken will depend on the severity, frequency, evidence, and circumstances of the incident.

## 9. Good-Faith Reports

Reports made honestly and with reasonable evidence are protected from retaliation.

A report does not need to prove misconduct by itself. The purpose of reporting is to allow the maintainers to investigate.

Knowingly submitting fabricated evidence, malicious false reports, or reports intended to harass another participant is itself unacceptable behavior.

## 10. Scope

This Code of Conduct applies to project-controlled spaces, including:

- GitHub repositories and discussions
- Issue trackers
- Pull requests
- Project chat or community spaces operated by the project
- Official project events
- Other spaces when a participant is acting in an official project capacity

## 11. Interpretation

The project prefers direct communication, precise criticism, and evidence-based discussion.

The following distinction is fundamental:

> **Be ruthless about bugs. Be respectful about people.**

The project may update this Code of Conduct when the community or project structure changes.
